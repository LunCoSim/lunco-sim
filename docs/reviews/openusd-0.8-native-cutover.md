# Rust OpenUSD 0.8 migration review

Status: native dependency cutover and bounded cleanup validated. Remaining
layer-stack and SDK work is listed below.

## Dependency and ownership

Cargo pins the maintained `openusd`, `openusd-schemas`, and `openusd-build`
crates to 0.8.0. The pinned Rust toolchain is `nightly-2026-03-29`
(Rust 1.96), satisfying the dependency's minimum compiler version.
The vendored 0.5 fork and its Cargo patches are removed.

Native OpenUSD owns schema declarations/defaults, prim definitions, composed
attribute values, transforms, visibility, collection membership, source spec
sites, change classification, Sdf spec copying, and layer codecs.
`lunco-usd-authoring` registers compiled standard/project declarations and the
existing PhysX subset through native schema families. `SchemaMetadata` retains
application inspector hints and scalar length facts; it does not implement
schema inheritance, defaults, types, or variability. PhysX declarations remain
a reconstructed subset, without a vendor-conformance claim.

The custom runtime schema ingestion/polling, copied standard schema resources,
USDA text-edit tokenizer, interpolation implementation, transform facade,
binary empty-layer substitution, patched asset-identity annotation, and
Python schema generator are removed. Project schema artifacts are generated by
`openusd-build`; JSON is used only for the external plugin manifest.

`ResolveUsdTarget` resolves the current document layer stack with its admitted
recipe through one native stage. It reports `document_composition`. Native
validity, composition-arc facts, and spec sites determine existence and scope.
It does not infer a target from local specs or wait for a derived live stage.
Production assertions use this current contract.

Transient document composition copies authored base specs through native Sdf
operations into the identified root; runtime and view use native USDC buffers.
The original root identity anchors relative arcs.
Binary document preparation retains parsed layer data without requesting text.
Inheritance therefore composes without USDA export; source display, text
snapshots, and USDA export retain the explicit SDK serialization diagnostic.

USD source assets retain exact bytes. File, browser, Twin, discard, restart,
and session-restore preparation use native format decoding. Save selects the
native writer by destination extension; `.usdc` receives binary USD. Unmodified
USDA retains its original source. Serialization failure leaves the file and
saved watermark untouched and records a rejected/failed command result.

Continuous animation samples the owned live native stage; a prepared snapshot
serves only its captured times. It never constructs a sampling stage per frame
or implements interpolation. The one-time live-stage build remains an SDK
`!Send` boundary; this review makes no performance acceptance claim.

Dependency inspection uses the native file-format reader, native ListOp
evaluation on an analysis copy, and the native asset-path visitor. Authored
spellings remain sorted before anchoring so reanchoring preserves correspondence.
Deleted/reordered reference items do not cause fetches. Source opinions are not
modified. UsdUtilsComputeAllDependencies is unsuitable for this reader because
its expansion contract refuses variable expressions and UDIM patterns supported
by the stage's asset-value path.

These changes are generic mechanisms and invariant checks. No changeable
scenario/lifecycle selection policy was added in Rust. The native collection
failure fact is consumed by authored `lint_usd.rhai` policy.

## Required remaining work

1. The upstream 0.8.0 USDA writer emits the internal `inheritPaths` name instead
   of the standard `inherits` keyword. Pixar OpenUSD 26.08 rejects its output.
   The same mapping remains in the inspected upstream head
   `4467984b4f32b9e1569635b8b578deb4cbef8744`. The authoring owner rejects this
   serialization before publishing/writing it. There is no output-rewriting
   shim or alternate text writer. The canonical schema source was restored
   exactly through the document API and remains Pixar-readable. Its obsolete
   generator comment cannot be updated through a structural save until this
   native writer defect is fixed; current generation instructions are in the
   runbooks. A fixed native library must replace the guard and its rejection
   assertion with successful interoperability coverage.
2. `author::compose_layers`, the document's composed-data memo, and consumers
   of its merged source remain. Runtime mounting, previews, persistence, and
   queries must carry explicit native layer stacks/recipes before that merge
   and its tests can be deleted. Native `Stage::flatten` resolves and removes
   composition arcs, so it cannot replace an authored-layer merge or save.
   This review does not claim that all reinvention or fallback paths are gone.
3. USDZ exists in the native SDK, but package paths and package-layer provenance
   are not wired through the application's storage/source-document boundary.
   The migrated loaders advertise `.usd`, `.usda`, and `.usdc` only.
