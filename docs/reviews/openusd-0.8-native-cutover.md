# Rust OpenUSD 0.8 migration review

Status: native dependency cutover and bounded cleanup validated. Remaining
layer-stack and SDK work is listed below.

## Dependency and ownership

Cargo pins the maintained `openusd`, `openusd-schemas`, and `openusd-build`
crates to 0.8.0. The pinned Rust toolchain is `nightly-2026-03-29`
(Rust 1.96), satisfying the dependency's minimum compiler version.
The vendored 0.5 fork and its Cargo patches are removed.

Native OpenUSD owns schema declarations/defaults, prim definitions, composed
attribute values, transforms, visibility, collection membership, source spec
sites, change classification, Sdf spec copying, and layer codecs.
`lunco-usd-authoring` registers compiled standard/project declarations and the
existing PhysX subset through native schema families. `SchemaMetadata` retains
application inspector hints and scalar length facts; it does not implement
schema inheritance, defaults, types, or variability. PhysX declarations remain
a reconstructed subset, without a vendor-conformance claim.

The custom runtime schema ingestion/polling, copied standard schema resources,
USDA text-edit tokenizer, interpolation implementation, transform facade,
binary empty-layer substitution, patched asset-identity annotation, and
Python schema generator are removed. Project schema artifacts are generated by
`openusd-build`; JSON is used only for the external plugin manifest.

`ResolveUsdTarget` resolves the current document layer stack with its admitted
recipe through one native stage. It reports `document_composition`. Native
validity, composition-arc facts, and spec sites determine existence and scope.
It does not infer a target from local specs or wait for a derived live stage.
`InspectUsdDocument` uses the same native document-stage owner for prim types,
children, attributes/schema defaults, metadata, reference lists, and spec sites.
Composed fields report `document_composition`; authored root/runtime/view
opinions remain separate. Dependencies use the native asset visitor on parsed
layer data; layer statistics count authored specs without serialization.
Inspection does not request USDA text, including for binary inheritance.
Native read failures reject the query. Production assertions use this contract.
Document edit-unit conversion also reads
that native composed stage through the shared `StageMetrics` owner; it does
not read a custom merged layer or treat native errors as omitted metadata.

Typed attribute and connection preflight also uses the current document's native
stage, with the projected stage id used only for dynamic runtime ports. The
separate authored-data preflight and projected-value selection are removed.
Native prim types select scalar length declarations; transform inverses retain
the native composed operation order. `StageRecipe` now carries an explicit
session layer, and native document/runtime stage opening shares
`lunco-usd-compose::open_recipe`. Captured session content participates in replay
identity; missing session bytes are rejected. Unmounted authoring captures the
separate native root/runtime/view layers and fetches their dependency closure
within one budget. It does not serialize a custom merged layer.

Canonical topology snapshots preserve native root/session identities and the
full admitted byte closure, including unopened dependencies. The native change
sink records edited layer identities; capture copies only those authored layers
to send-safe `Sdf Data`. Encoding occurs on the worker through the native codec
selected by the original identifier. Unedited binary layers retain their
admitted buffers. The empty-closure substitution for foreign resolvers is
removed. Authoring-context capture failures terminate commands before mutation.

Transient document composition copies authored base specs through native Sdf
operations into the identified root; runtime and view use native USDC buffers.
The original root identity anchors relative arcs.
Binary document preparation retains parsed layer data without requesting text.
Inheritance therefore composes without USDA export; source display, text
snapshots, and USDA export retain the explicit SDK serialization diagnostic.

USD source assets retain exact bytes. File, browser, Twin, discard, restart,
and session-restore preparation use native format decoding. Save selects the
native writer by destination extension; `.usdc` receives binary USD. Unmodified
USDA retains its original source. Serialization failure leaves the file and
saved watermark untouched and records a rejected/failed command result.

Continuous animation samples the owned live native stage; a prepared snapshot
serves only its captured times. It never constructs a sampling stage per frame
or implements interpolation. The one-time live-stage build remains an SDK
`!Send` boundary; this review makes no performance acceptance claim.

Dependency inspection uses the native file-format reader, native ListOp
evaluation on an analysis copy, and the native asset-path visitor. Authored
spellings remain sorted before anchoring so reanchoring preserves correspondence.
Deleted/reordered reference items do not cause fetches. Source opinions are not
modified. The bounded asset-closure owner admits raw bytes to the format owner;
Scene Files and networking packaging use native USD decoding for USDA and USDC.
Format errors retain their diagnostic instead of failing a generic UTF-8 gate. UsdUtilsComputeAllDependencies is unsuitable for this reader because
its expansion contract refuses variable expressions and UDIM patterns supported
by the stage's asset-value path.

These changes are generic mechanisms and invariant checks. No changeable
scenario/lifecycle selection policy was added in Rust. The native collection
failure fact is consumed by authored `lint_usd.rhai` policy.

opinions. Document input publication has a scoped owner, a retained asset handle,
and revision/retirement fences. Every root gets distinct runtime/view/session
identities; incremental and deferred reference edits select their named target.
The root-copy owner establishes the native pseudo-root before `SdfCopySpec`.

atomic groups, reserves referenced/inactive names, scopes counters to the

## Native document consumers and reference admission

Mount attachment/detachment and deletion guards read native validity, schemas,
relationships and connections. Ambient authoring traverses native composed
DomeLights, consuming schema defaults, exposure and activity in f64; connected
or time-varying inputs reject document authoring before edits. Omitted
`texture:file` follows UsdLux's untextured semantic.

Preview text exports authored source and native `Stage::flatten` on a worker for
read-only display. Document generation and source-plan identity fence its
result. `InspectUsdViewport.text_error` exposes failures. Rendering cadence does
not invalidate an unchanged document text snapshot.

Reference batches admit their complete native closure and the existing Rhai
composition decision before ordered authoring. The native change sink owns ECS
materialization. Queued reference replay, lightweight-root substitution,
promotion state, per-instance reader selection and their tests are removed.
`ReferenceLayerInputs` owns asynchronous native preparation and source residency;
active reference roots complete the document's projection lease. Empty asset
paths remain native internal references and cause no external fetch.
`clock_snapshot().simulation_progress` reports ordered blockers as typed facts.

The integrated production build and application all-target check pass. The
native owner test targets compile without introduced warnings. Production
`COMPONENT_DETACH` passes four checks, including incoming-connection rejection,
on port 4206. `SOCKET_ATTACH_REJECTION` passes three checks on 4207. Dynamic
reference allow/reject gates pass on 4208/4209, including partial composition and
the terminal projection diagnostic. Native ambient authoring passes four checks

## Required remaining work

1. The upstream 0.8.0 USDA writer emits the internal `inheritPaths` name instead
   of the standard `inherits` keyword. Pixar OpenUSD 26.08 rejects its output.
   The same mapping remains in the inspected upstream head
   `4467984b4f32b9e1569635b8b578deb4cbef8744`. The authoring owner rejects this
   serialization before publishing/writing it. There is no output-rewriting
   shim or alternate text writer. The canonical schema source was restored
   exactly through the document API and remains Pixar-readable. Its obsolete
   generator comment cannot be updated through a structural save until this
   native writer defect is fixed; current generation instructions are in the
   runbooks. A fixed native library must replace the guard and its rejection
   assertion with successful interoperability coverage.
2. `author::compose_layers`, the document's composed-data memo, and its
   dependent-layer projection consumer remain. Mount validation, deletion
   guards, ambient authoring and read-only composed-text previews use native
   stages. The dependent-layer consumer must use its native owner before that
   merge and its tests can be deleted. Loader metadata settings
   are applied on first asset admission; document publication into an already
   admitted source asset must preserve its current native input ownership and
   reload graph. That lifecycle still requires production coverage.
   Native `Stage::flatten` resolves and removes composition arcs, so it cannot replace an authored-layer merge or save.
   This review does not claim that all reinvention or fallback paths are gone.
3. USDZ exists in the native SDK, but package paths and package-layer provenance
   are not wired through the application's storage/source-document boundary.
   The migrated loaders advertise `.usd`, `.usda`, and `.usdc` only.
