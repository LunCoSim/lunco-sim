# Native Modelica semantic zoom

Requested behavior: a component icon gives way to its actual internal diagram as it grows on screen, recursively. The existing canvas already owns cursor-centered wheel zoom, pan and ordinary double-click drill-in; the missing piece was inline composition of its native scenes.

The authoritative source is the shared Rumoca session. `DiagramSnapshot` supplies resolved declarations and connections; base-class connections now follow the same inheritance as the existing inherited member projection. Base resolution uses Rumoca navigation, not a second name resolver. Its source-symbol index also owns class-to-document lookup, including cross-file children.

`canvas_diagram::semantic` prepares frozen child scenes inside the existing cancellable background projection job. It reuses `project_scene`, `NodesLayer` and `EdgesLayer`; no alternative graph renderer, new parser, or dependency was introduced. A global node budget and cycle/depth guards bound expansion. Leaves display the parser's complete source span. Child instance paths prefix connection and icon telemetry lookups independently of authored local labels. Nested UI is disabled for edits; the existing double-click editor remains authoritative.

`DiagramPresentationSettings.semantic_zoom` owns the opt-in persisted mode, consumed by the canvas renderer and exposed through the existing typed `ConfigureDiagramPresentation` command and Appearance UI. Ordinary icon editing retains its existing presentation. The Modelica host extends its own viewport range while this mode is active; other canvas consumers retain their bounds.

Hook review: owner is the Modelica canvas, inputs are immutable typed scenes and the continuous viewport scale, output is clipped rendering. Scope is the current diagram/tab; lifetime is its revision-fenced projection. This is continuous rendering over authored Modelica facts, not authored lifecycle policy. The existing typed presentation setting provides the choice to UI/API/Rhai; no separate routing hook is needed.

Validation: the focused `semantic_zoom_projects_inherited_cross_file_hierarchy_and_scoped_connections` test covers cross-file source ownership, nested projection, inherited connections, scoped telemetry paths, visible caps and cancellation. Production native screenshots and factory experiments are retained beside the authored factory model, not loaded by shared Rust tests. The UI work itself adds no dependency. Separately approved Rumoca repairs are integrated through exact Git revision `a90c7b9d3afad9c4f38dec223d5f0f5d52df2773`, published in LunCoSim/rumoca. No sibling checkout is required.

Native testing also exposed an atlas allocation failure at extreme zoom in the existing static diagram-text renderer. The shared `diagram_text_galley` helper now rasterizes glyphs at a bounded physical size and uses epaint's supported galley mesh transform to preserve the requested screen dimensions. Both diagram text and icon text consume it, as do semantic source leaves. This is a renderer repair; authored fonts and geometry are not clamped. The focused large-text test exercises a 100,000-point label, and production captures exercise transitions beyond the former zoom range.

Nested previews consume matching text/AST snapshots from resident editor documents, whose compiler entries intentionally carry parsed syntax without source text. Library source remains session-owned. The existing global Modelica source epoch rejects stale background results and invalidates nested previews when any source changes; no compiler lock or source scan is added to a UI frame.

The existing `SceneCameraAudit` now includes each candidate's actual world position, forward direction and projection. Native inspection established that the factory camera and geometry were correct; the black view came from the authored light's unnormalized intensity and the default lunar exposure. The factory now authors normalized lux and standard USD photographic exposure, verified in the live scene. No renderer-wide lighting policy was changed.
